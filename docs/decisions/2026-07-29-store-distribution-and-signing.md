# การกระจายผ่านสโตร์ และการตัดสินใจเรื่อง code signing

- วันที่ 2026-07-29
- สถานะ ตัดสินแล้ว (Track C ข้อ store distribution decision และ signing decision)
- ปิดสองข้อที่ [ROADMAP](../../ROADMAP.md) Track C ระบุว่าต้อง "record the outcome
  either way" เอกสารนี้จึงบันทึกทั้งสิ่งที่ตัดสินและสิ่งที่ตัดสินว่าไม่ทำ

## คำถามที่ต้องตอบ

Track C ให้ตัดสินรายช่องทางว่าจะส่ง extension เข้า Chrome Web Store และส่ง
packaging manifest เข้า winget กับ scoop หรือไม่ โดยยอมรับภาระการดูแลที่ตามมา
และให้ทบทวนจุดยืน unsigned-by-design เมื่อการกระจายกว้างขึ้น manifest ทั้งสี่ไฟล์
พร้อมอยู่แล้วที่ `packaging/` (มี `scripts/update_packaging.py` อัปเดตให้ทุกรีลีส)
ส่วน listing copy สองภาษา privacy policy และ permissions justification พร้อมอยู่ที่
`docs/store/` สิ่งที่ขาดคือการตัดสินใจ ไม่ใช่ของ

## ข้อเท็จจริงที่ใช้ตัดสิน (ค้น 29 ก.ค. 2569)

**Azure Artifact Signing ใช้กับไทยไม่ได้** บริการ managed signing ของ Microsoft
(ชื่อเดิม Trusted Signing) เป็นทางที่ถูกที่สุดในตลาด ราคา Basic 9.99 ดอลลาร์ต่อเดือน
ต่อ 5,000 ลายเซ็น แต่ [FAQ ทางการ](https://learn.microsoft.com/en-us/azure/artifact-signing/faq)
ที่อัปเดต 22 มิ.ย. 2569 ระบุว่าใบรับรอง Public Trust เปิดให้องค์กรใน สหรัฐ แคนาดา
สหภาพยุโรป สหราชอาณาจักร และนักพัฒนาบุคคลใน สหรัฐ กับแคนาดา เท่านั้น ไทยไม่อยู่
ในรายชื่อทั้งสองแบบ และบริการนี้ไม่ออกใบรับรอง EV เลย

**การเซ็นไม่ได้ทำให้จอเตือนหายทันทีอีกแล้ว** ตั้งแต่สิงหาคม 2567 Microsoft ถอด
EV Code Signing OID ออกจาก Trusted Root Program ใบรับรองทุกแบบถูกปฏิบัติเท่ากัน
FAQ เดียวกันระบุว่า SmartScreen สะสม reputation อัตโนมัติและจอเตือนหยุดขึ้นเมื่อ
hash ของไฟล์มีประวัติดาวน์โหลดมากพอ ประโยชน์ที่เหลือจากการเซ็นจึงเป็นสองอย่าง คือ
ชื่อผู้พัฒนาแสดงแทนคำว่า Unknown publisher และ reputation เกาะกับผู้เซ็นแทนที่จะ
เริ่มนับใหม่ทุกไฟล์

**ทางที่เหลือคือซื้อใบรับรองจาก CA** ราคาที่พบจากหน้าเว็บ reseller ในวันที่ค้น อยู่
ราว 220 ถึง 230 ดอลลาร์ต่อปีสำหรับ Sectigo OV และราว 250 ดอลลาร์ต่อปีขึ้นไปสำหรับ
EV แบบ sole proprietor ทุกแบบต้องเก็บ private key ใน hardware token หรือ HSM ตาม
ข้อบังคับ CA/Browser Forum และตั้งแต่ 15 ก.พ. 2569 อายุใบรับรองสูงสุดเหลือหนึ่งปี
ยังไม่ได้ตรวจว่า CA เหล่านี้รับผู้ขอบุคคลธรรมดาที่อยู่ในไทยหรือไม่ เพราะการตัดสินใจ
ไม่ได้ไปถึงจุดนั้น

**Chrome Web Store** ค่าธรรมเนียม 5 ดอลลาร์เป็นค่าบัญชีนักพัฒนาครั้งเดียว ไม่ใช่
ต่อ extension รีวิวปกติไม่กี่วันถึงหลายสัปดาห์ ฝั่งเรามีข้อได้เปรียบตรงสิทธิ์ที่ขอแคบ
(storage clipboardWrite sidePanel กับ host เฉพาะ localhost:8000 และ content script
ระบุหกไซต์ ไม่ใช่ all_urls) แต่มีข้อเสียเปรียบที่หนักกว่า คือ extension ทำงานไม่ได้
ถ้าไม่มี backend รันอยู่ ผู้รีวิวที่เปิดมาจะเจอข้อความว่า backend ยังไม่ทำงานทุกปุ่ม
และนโยบายระบุว่าฟังก์ชันที่ใช้ไม่ได้ตอนรีวิวเป็นเหตุให้ปฏิเสธได้ ช่อง test
instructions มีให้กรอกแต่เอกสารทางการอธิบายว่ามีไว้สำหรับ credential หรือบัญชี
แบบเสียเงิน ไม่ได้พูดถึงกรณีที่ผู้รีวิวต้องติดตั้ง companion app ที่ไม่ได้เซ็น

## สิ่งที่ตัดสิน

1. **winget ส่ง** manifest พร้อม การถอนทำได้ด้วย PR ลบไฟล์เวอร์ชันนั้น (ทีละเวอร์ชัน
   ต่อหนึ่ง PR) ภาระต่อเนื่องคือ PR ต่อหนึ่งรีลีส ซึ่ง `update_packaging.py` เตรียม
   ไฟล์ให้แล้ว สิ่งที่ถอนไม่ได้คือประวัติสาธารณะใน git ของ winget-pkgs เครื่องที่
   ติดตั้งไปแล้ว และ publisher identifier `Teerapat-Vatpitak.AIGuard` ที่ติดถาวร
2. **scoop ทำเป็น bucket ของโครงการเอง** ไม่ส่งเข้า Extras ผู้ใช้พิมพ์
   `scoop bucket add` เพิ่มหนึ่งครั้ง แลกกับการที่เราแก้หรือถอนได้เองทันทีโดยไม่ต้อง
   ผ่าน maintainer ของ bucket กลาง การติดตั้งตรงจาก URL manifest ใน repo ยังใช้ได้
   เหมือนเดิมสำหรับคนที่ไม่อยากเพิ่ม bucket
3. **Chrome Web Store ยังไม่ส่ง** ไม่ใช่เพราะไม่อยากส่ง แต่เพราะเงื่อนไขการรีวิว
   ต้องการให้ผู้รีวิวใช้งานได้จริง ซึ่งแปลว่าต้องมีเส้นทางติดตั้ง backend ที่ง่ายพอ
   จะเขียนเป็น test instructions ได้ก่อน winget คือเส้นทางนั้น จึงทบทวนอีกครั้งเมื่อ
   แพ็กเกจ winget ผ่านและมีคำสั่งติดตั้งบรรทัดเดียวให้อ้างอิง
4. **คง unsigned ต่อ** ทางที่ถูกที่สุดปิดสำหรับผู้พัฒนาที่อยู่ในไทย และทางที่เหลือ
   มีต้นทุนราวเจ็ดถึงแปดพันบาทต่อปีสำหรับโครงการโอเพนซอร์สที่ไม่มีรายได้ โดยที่จ่าย
   แล้วผู้ใช้ก็ยังเจอ SmartScreen จนกว่าจะสะสมยอดดาวน์โหลดอยู่ดี ความน่าเชื่อถือ
   ยังมาจากการตรวจสอบได้ตามเดิม คือ `SHA256SUMS` กับ GitHub build provenance ของ
   ทุกรีลีส ซึ่งพิสูจน์ที่มาและความครบถ้วนได้แข็งกว่าใบรับรอง แลกกับการที่ผู้ใช้ต้อง
   ยอมกดผ่านจอเตือนครั้งแรก

## เงื่อนไขที่จะทำให้กลับมาทบทวน

- Artifact Signing เปิดรับผู้พัฒนาที่อยู่ในไทย หรือโครงการมีนิติบุคคลในประเทศที่
  รองรับ ตอนนั้นต้นทุนจะเหลือหลักร้อยบาทต่อเดือนและการตัดสินใจข้อ 4 เปลี่ยนทันที
- มีผู้สนับสนุนค่าใบรับรอง หรือโครงการมีรายได้ที่รองรับค่าใช้จ่ายรายปีได้
- winget เข้าแล้วและมีเสียงจากผู้ใช้ว่าจอเตือนเป็นอุปสรรคจริง ไม่ใช่แค่ที่เราคาดเอง
- Chrome Web Store เมื่อเส้นทางติดตั้ง backend ง่ายพอจะเขียนใน test instructions

## สิ่งที่ยังไม่ทำ

- การส่งจริงทั้ง winget PR และการสร้าง bucket repo เป็นการเผยแพร่ออกนอก จึงเป็นงาน
  ที่เจ้าของกดเอง ตามที่ [packaging/README](../../packaging/README.md) กำหนดไว้แต่แรก
- ยังไม่ได้ยืนยันค่า `AppsAndFeaturesEntries` กับ registry ของเครื่องที่ติดตั้งจริง
  ซึ่ง `packaging/README` บันทึกไว้ว่าเป็นค่า best-effort จนกว่าจะตรวจ
- ยังไม่ได้ทดสอบว่าการเปิดแอปที่ scoop แตกไฟล์มาให้ ทำให้เจอ SmartScreen หรือไม่
  (installer ไม่ถูกรัน แต่ Mark of the Web อาจยังติดมากับไฟล์ที่ดาวน์โหลด)
