# ย้าย UI ทุกพื้นผิวไปเป็น Material Design 3

- วันที่ 2026-07-29
- สถานะ ตัดสินแล้ว เจ้าของกำหนดทิศเอง
- แทนที่ระบบสไตล์เดิมสองรุ่นในวันเดียวกัน คือ "Vault Door" จาก
  [ADR 2026-07-07](2026-07-07-ui-redesign-aiguard-design.md) และรุ่นขาวมินิมอลที่ merge
  ไปก่อนหน้าใน `0f04966` เอกสารทั้งสองฉบับนั้นคงไว้ตามเดิม ไม่เขียนทับ

## สิ่งที่ตัดสิน

UI ทุกพื้นผิวของโครงการใช้ Material Design 3 ครอบคลุมห้าที่ คือ desktop app,
side panel ของ extension, แถบและ overlay ที่ฉีดเข้าหน้าเว็บ, task pane ของ Office
add-in และหน้า playground

## ทำอย่างไรให้ตรงสเปกจริง ไม่ใช่แค่หน้าตาคล้าย

ค่าทุกตัวมาจากต้นทางของ Google ไม่ได้กะเอา type scale shape scale state layer
elevation และ mapping ของ color role ดึงจาก `material-web` ที่เวอร์ชัน v0.192
ส่วนจานสีสร้างจากสีแบรนด์ `#2563EB` ด้วย `@material/material-color-utilities`
ซึ่งเป็น implementation ของ HCT ที่ MD3 ใช้เอง ดังนั้นโทนที่ได้คือโทนที่อัลกอริทึม
ของสเปกผลิต ไม่ใช่การไล่สีใน sRGB ด้วยสายตา

ตัวเลขที่สำคัญและตรึงไว้ด้วยเทสแล้ว state layer 0.08 hover 0.12 focus 0.12 pressed
0.16 dragged shape 4 8 12 16 28 px และ full 9999 px กับตัวอย่าง type scale ห้าระดับ

**ไม่ใช้ไลบรารี `material-web`** เขียน CSS เองตามชื่อ token ของสเปก เหตุผลคือ
extension เป็น MV3 ที่มีข้อจำกัด CSP และการเพิ่ม web components ทั้งชุดเข้าไปในทุก
storefront แลกน้ำหนักกับสิ่งที่เราต้องการจริงไม่คุ้ม การใช้ชื่อ `--md-sys-*` ตาม
สเปกทำให้ถ้าวันหนึ่งจะใส่ไลบรารีจริง มันอ่าน token ชุดเดิมได้ทันทีโดยไม่ต้องแปลง

**สีต่อชนิด PII ในหน้า playground เป็น extended custom color** MD3 ไม่มี role
สำหรับจานสีแบบแยกหมวดแปดสี จึงใช้กลไก extended color คือคง hue เดิมที่ผู้ใช้จำได้
แล้วส่งผ่าน tonal process เดียวกัน ได้ container กับ on-container ที่ contrast
รับประกันได้ หน้านี้เป็นธีมมืด จึงใช้ tone 30 คู่กับ 90 ตามที่ role หลักของธีมมืดใช้

## สิ่งที่แลกไป

Office add-in ทำงานอยู่ใน Word Excel และ PowerPoint ซึ่งเป็นโฮสต์ที่ออกแบบด้วย
Fluent ของ Microsoft การใส่ MD3 ลงไปทำให้ task pane อ่านเป็นคนละภาษากับ ribbon
ที่อยู่เหนือมันอย่างชัดเจน ทั้งทรงปุ่มแบบแคปซูล จานสี และจังหวะระยะห่าง นี่คือราคาที่
รับไว้โดยรู้ตัวเพื่อให้ทุกพื้นผิวของผลิตภัณฑ์พูดภาษาเดียวกัน ถ้าผู้ใช้จริงสะดุด
พื้นผิวนี้คือที่แรกที่ควรได้รับการยกเว้น

MD3 ไม่มี role สำหรับคำว่า warning ข้อความเตือนที่ไม่ถึงขั้น error จึงใช้ tertiary
ซึ่งเป็น role ที่สเปกเตรียมไว้สำหรับ accent ที่ไม่ใช่ทั้ง primary และ error

## สิ่งที่ยังไม่ทำ

- ไม่ได้ทำ dynamic color ที่ดึงสีจาก wallpaper ของผู้ใช้ ซึ่งเป็นฟีเจอร์หนึ่งของ MD3
  บนแอนดรอยด์ เดสก์ท็อปกับเบราว์เซอร์ไม่มีช่องทางนั้น
- ไม่ได้ทำ motion transition ระดับ component ตาม MD3 มีแต่ state layer กับ
  easing token ที่ประกาศไว้แล้ว
- ยังไม่ได้ตรวจด้วยเครื่องมือ contrast อัตโนมัติทุกคู่สี ที่ตรวจแล้วคือคู่ที่
  ใช้จริงบนหน้าจอหลัก
